# VK-бот для записи к мастеру по волосам

Бот для сообщества ВКонтакте: считает примерную стоимость процедуры, ведёт
запись в свободные окошки, помнит график мастера и сам напоминает клиенту
о визите. Мастер работает один и ничего не настраивает вручную — расписание
складывается из записей, которые клиенты делают сами.

Работает сразу в двух мессенджерах — ВКонтакте и Telegram — на одной базе:
клиент из ВК и клиент из Telegram видят одно расписание и мешать друг другу
не могут. Написан на Python: ВКонтакте через `vk_api`, Telegram через Bot API,
оба на long polling. Данные — в SQLite рядом с кодом.

## Возможности

- **Расчёт стоимости**: процедура → длина волос → густота → вилка цены и
  длительность. Коэффициенты и прайс лежат в `config.py`.
- **Запись на время**: бот показывает только те дни и окошки, куда процедура
  реально влезает — с учётом рабочих часов, уборки между клиентами и запаса
  на дорогу.
- **Свои записи, отмена и перенос** — списком, с временем окончания
  и статусом. Перенос меняет время одним действием: старая запись снимается
  ровно тогда, когда удалось занять новое, поэтому остаться вообще без записи
  нельзя. Освободившееся время сразу возвращается в расписание.
- **Подписка на день**, если свободного времени нет: когда кто-то отменяется,
  бот пишет всем, кому это окошко подходит по длительности, и ведёт сразу
  к выбору времени.
- **Напоминание за сутки** с кнопками «Подтверждаю» и «Отменить запись».
  Неподтверждённая запись снимается за 12 часов до начала, и время уходит
  тем, кто его ждёт. **В день процедуры** приходит второе, короткое:
  «сегодня в 14:00, ждём вас» — с адресом и телефоном.
- **Мастер в курсе**: о новой записи, отмене и переносе бот пишет владельцу
  сообщества — процедура, время, цена и ссылка на клиента. Отмена в последний
  момент помечается отдельной строкой.
- **Кабинет мастера** — у владельца в главном меню:
  - **расписание**: ближайшие дни, а внутри дня — кто и когда придёт;
  - **отмена записи с причиной**: клиент получает её текстом, время
    возвращается в расписание и уходит тем, кто его ждал;
  - **закрытие времени**: выходной, отлучка на пару часов, отпуск или пауза
    «пока не открою». Записи, попавшие в закрытое время, отменяются разом —
    одной причиной, и каждый клиент получает её сам;
  - **график работы**: рабочие дни недели и часы меняются прямо в переписке,
    без правки файлов и перезапуска.
- **Лимиты**: до 5 активных записей и до 3 подписок на клиента. Переносу
  лимит не мешает — записей от него не прибавляется.

## Устройство

    main.py  →  schedule.py  →  db.py  →  config.py
       ↓
    messenger.py  →  ВКонтакте (vk_api)
                  →  Telegram (Bot API)

- `main.py` — диалог с клиентом: состояния, клавиатуры, тексты, фоновый
  планировщик напоминаний.
- `messenger.py` — прослойка над мессенджерами: отправка, сборка клавиатур,
  приём сообщений. Весь код, завязанный на ВКонтакте и на Telegram, спрятан
  здесь, каждый в своём классе (`VkMessenger`, `TgMessenger`) за общим
  интерфейсом. Диалог зовёт только методы этого интерфейса и про конкретный
  мессенджер не знает — один и тот же `main.py` обслуживает оба. Когда каналов
  два, каждый слушает сеть в своём потоке, а сообщения из обоих сходятся
  в одну очередь: принимаем параллельно, а обрабатываем по одному, чтобы
  запросы к общей базе не наступали друг другу на пятки.
- `schedule.py` — расписание: свободные окошки, записи, подписки, статусы.
- `db.py` — где лежат данные: соединение с базой, схема, уборка старого.
- `config.py` — только данные: прайс-лист, график мастера, лимиты.
- `config.cfg` — настройки этой установки: адрес, телефон, номер мастера,
  имя файла с ключом доступа. Всё, что своё у каждого, лежит здесь, а не
  в коде.
- `tests/` — четыре набора проверок и заглушка `vk_api`, чтобы гонять их
  без живого сообщества.
- `TESTING.md` — то, что проверяется руками: 68 сценариев с шагами.

Записи и подписки лежат в `bot.db` (SQLite). Имена колонок совпадают с ключами
словарей в коде, поэтому в данные можно смотреть глазами:

```bash
sqlite3 bot.db "select * from bookings"
```

Почему SQLite и что именно ограничивает размер базы, откуда взялся лимит в 5
рядов клавиатуры и как устроены подписки с напоминаниями —
в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Нужен Python 3.10 или новее и сообщество ВКонтакте, где вы администратор.

```bash
git clone <адрес репозитория>
cd vk_bot

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

На Windows то же самое, только исполняемые файлы окружения лежат
в `.venv\Scripts`, а не в `.venv/bin`:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Дальше нужен ключ доступа сообщества: **Управление сообществом → Работа с API →
Ключи доступа**, права — сообщения сообщества. Полученный ключ положите
в файл `token.txt` в корне проекта (он в `.gitignore` и в репозиторий
не попадает):

```bash
echo "ваш_ключ_доступа" > token.txt
```

Вместо файла можно задать переменную окружения `VK_TOKEN` — она важнее файла.
Так бот запускается там, куда код приезжает через git и `token.txt` не
попадает. Путь к базе тоже можно задать переменной `DB_FILE`, если она должна
лежать не рядом с кодом.

**Telegram** нужен, только если он указан в `platform` (см. «Настройки»). Ключ
для него выдаёт [@BotFather](https://t.me/BotFather): напишите ему `/newbot`,
придумайте имя, и он пришлёт токен. Положите этот токен в файл `tg_token.txt`
рядом с кодом (он тоже в `.gitignore`) или в переменную окружения `TG_TOKEN` —
устроено так же, как у ВК, и по той же причине: ключ в репозиторий попадать
не должен. Пока в `platform` нет `tg`, файл не нужен, и бот его не спрашивает.

```bash
echo "ваш_токен_от_BotFather" > tg_token.txt
```

И откройте `config.cfg` — без него бот не запустится. Что в нём писать,
разобрано ниже, в разделе «Настройки».

Часовой пояс бот выставляет себе сам — `TIMEZONE` в `config.py`. Всё время
в расписании локальное, а сервер обычно живёт по UTC, поэтому пояс не берётся
из системы: иначе рабочий день мастера уехал бы на три часа.

И включите боту возможность отвечать: **Управление сообществом → Сообщения →
Настройки для бота → Возможности ботов: Включены**. Без этого VK вернёт
ошибку 912.

Запуск:

```bash
.venv/bin/python main.py
```

На Windows:

```powershell
.venv\Scripts\python.exe main.py
```

Бот работает на long polling — домен, SSL и вебхуки не нужны.

В PyCharm то же окружение подключается через **File → Settings → Project →
Python Interpreter → Add Interpreter → Existing** и путь
`.venv\Scripts\python.exe` в каталоге проекта.

```
ModuleNotFoundError: No module named 'vk_api'
```

Эта ошибка означает ровно одно: бот запущен интерпретатором, в котором
зависимостей нет — обычно системным Python вместо окружения. Лечится либо
переключением интерпретатора, либо установкой зависимостей в тот, которым
запускаете: `<путь к python.exe> -m pip install -r requirements.txt`.

Первая строка в консоли при удачном запуске выглядит так:

```
Бот запущен 03.08.2026 19:28 (Europe/Moscow), база ...\bot.db. Ctrl+C — остановить.
```

Если вместо неё длинная трассировка с `SSLError` или `MaxRetryError` —
до `api.vk.com` не дошёл запрос: интернет, прокси или антивирус, а не бот.

Похожая строка про `api.telegram.org` в консоли (`Telegram недоступен: …`,
бот при этом повторяет попытку каждые 5 секунд) значит то же самое: до Telegram
не дошёл запрос. В некоторых сетях его адрес закрыт, а ВКонтакте при этом
работает; тогда нужен доступ к `api.telegram.org` через VPN. Маршрутизацию бот
на себя не берёт — это дело сети или VPN-клиента, а не кода.

## Настройки

Настройки живут в двух местах, и делятся они не по важности, а по тому, кто
их меняет.

**`config.cfg` — то, что своё у каждой установки.** Обычный ini-файл, правится
без Python; поставить бота другому мастеру — значит поправить его и положить
рядом свой `token.txt`.

```ini
[bot]
platform = vk, tg

[community]
token_file = token.txt
owner_id = 203719182

[salon]
address = г. Пенза, ул. Московская, д. 999А
phone = +7 777 777-77-77
```

- `platform` — мессенджеры, в которых работает бот. Поддерживаются `vk` и `tg`;
  можно указать оба через запятую (`vk, tg`), и тогда бот поднимет оба канала
  на одной базе. По умолчанию, если раздел `[bot]` не писать вовсе, работает
  один `vk`. Это то место, где набор мессенджеров выбирается «в момент запуска»:
  сменил значение — сменил каналы, а код в `main.py` тот же. Для `tg` рядом
  с кодом должен лежать `tg_token.txt` (или быть задан `TG_TOKEN`) — иначе
  канал не поднимется.
- `token_file` — файл, в котором лежит ключ доступа. Сам ключ в настройках
  не пишем: `config.cfg` едет в git, а ключ туда попадать не должен.
- `owner_id` — номер мастера ВКонтакте. По нему бот шлёт уведомления
  о записях и открывает кабинет. Ноль или пусто — уведомления и кабинет
  выключены; так и оставляют в чужой копии проекта.
- `address` и `phone` — их клиент видит в приветствии, при подтверждении
  записи, после записи и в напоминаниях. Без них он спросит адрес у мастера
  в личку, то есть ровно то, от чего бот и должен избавить.

Правила простые: значение — это всё, что после `=` до конца строки, кавычки
не нужны, решётка в середине строки остаётся обычным символом. Все строки
обязательны — забытую или пустую бот не проглотит молча, а остановится
и скажет, чего не хватает. Исключения два: `owner_id`, у которого ноль —
осмысленное значение, и весь раздел `[bot]` — его можно не писать, тогда
мессенджером будет ВКонтакте.

**`config.py` — то, что меняет мастер вместе с ценами.** Услуги с базовой
ценой и длительностью, коэффициенты за длину и густоту волос, рабочие дни
и часы по умолчанию, время на уборку между клиентами, шаг сетки времени,
лимиты записей и подписок, за сколько часов напоминать и отменять. Добавили
услугу в `SERVICES` — кнопка в боте появится сама.

Там же `hint` у длины и густоты — короткие расшифровки вроде «до плеч». Свою
длину клиент ещё представляет, а густоту оценить не может, и без подсказки
выбирает наугад — а от ответа зависят и цена, и сколько времени занять.

Чтобы уведомления дошли, **владелец должен хотя бы раз написать сообществу**:
ВКонтакте не даёт боту писать первым тому, кто с ним не заговаривал.

Рабочие дни и часы (`WORK_DAYS`, `WORK_START`, `WORK_END`) в файле остаются
значениями по умолчанию: как только мастер поменяет график в кабинете,
бот берёт его из базы, а настройки в коде больше не смотрит. Чтобы вернуться
к ним, достаточно очистить таблицу `settings`.

## Проверки

Расписание, база и перезапуск проверяются автоматически — четыре набора
в `tests/`, всего 350 проверок (347 под Windows: проверка часового пояса
требует `tzset()`, которого там нет, и три честно пропускаются).

```bash
.venv/bin/python tests/test_db.py        # 58  схема, запросы, потоки, уборка
.venv/bin/python tests/test_schedule.py  # 154 окошки, записи, подписки, статусы
.venv/bin/python tests/test_restart.py   # 100 живой диалог с перезапусками
.venv/bin/python tests/test_deploy.py    # 38  настройки, ключ, база, пояс
```

На Windows — `.venv\Scripts\python.exe tests\test_db.py` и так далее.

Настоящий `vk_api` для них не нужен: рядом лежит заглушка (`tests/stub/`),
она подставляется в `sys.path` раньше библиотеки, складывает отправленные
сообщения в список и не ходит в сеть. Каждый набор работает на своей базе
рядом с собой и в конце проверяет, что живая `bot.db` не тронута.

Всё остальное — тексты, кнопки, порядок экранов, уведомления мастеру —
проверяется руками по [TESTING.md](TESTING.md): там 68 сценариев с шагами
и ожидаемым результатом, стенд, протокол и способ проверить напоминания,
не ожидая суток.

## Версия базы

Схема помечена номером (`PRAGMA user_version`). Если код ждёт одну версию,
а база сделана другой, бот не запускается и говорит об этом прямо. Переноса
данных между версиями нет: пока записи учебные, базу проще удалить — новая
создастся сама.

Появятся настоящие клиенты — вместо остановки понадобится миграция.

## Что дальше

Готово: расчёт цены, запись, отмена и перенос, подписки на освободившиеся
окошки, напоминания с подтверждением и автоотменой, второе напоминание в день
процедуры, уведомления мастеру и его расписание, данные в SQLite. Работа сразу
в ВКонтакте и Telegram на одной базе — второй мессенджер подключился, не тронув
ни диалог, ни расписание. Перезапуск
бота не сбивает клиента с его шага: незаконченный диалог продолжается с того
же места. Старые записи, прошедшие подписки и брошенные диалоги бот убирает
сам раз в сутки, а ключ доступа и путь к базе умеет брать из переменных
окружения — это то, что нужно для запуска не на своём компьютере.

В планах: деплой на хостинг — конфигурация Amvera, постоянное хранилище под
базу и раздел про резервную копию.
